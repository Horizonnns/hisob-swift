# Hisob — правила разработки (iOS)

Личный учёт денег: источники дохода (места работы) и личные траты по месяцам
с переносом остатка. Перенос веб-версии (Next.js) на нативный iOS.

## Стек
- Swift 6 + SwiftUI, минимальная цель iOS 17
- Архитектура: MVVM + Clean Architecture
- Домен — локальный SwiftPM-пакет `HisobCore` (без импорта SwiftUI)
- Хранение: пока `InMemoryLedgerRepository`; далее SwiftData + синхронизация
  с Postgres (решение по бэкенду ещё не зафиксировано, см. `docs/model.md`)
- Сеть: URLSession; DI — передачей зависимостей в инициализаторы

## Архитектура
- Слои: UI / domain / data. Зависимости строго вниз (UI → domain → data),
  НИКОГДА обратных.
- Граница домена держится физически: `HisobCore` — отдельный пакет, UI в него
  просочиться не может.
- Навигация: TabView с 3 табами (Месяц, Аналитика, Настройки), каждый со своим
  NavigationStack; центральный AppRouter (Observable); единый
  destinationView(for: Route).

## Доменная модель (главное)
- Источник дохода НЕ владеет тратами. Он отвечает только на вопрос «сколько
  принёс в этом месяце». Личные траты финансируются суммарным доходом.
- Цепочка переноса остатка — одна на пользователя, сквозь смену работы.
- У источника есть `endedAt` — без него завершённая работа начисляет доход
  бесконечно вперёд.
- Деньги — только `Decimal` (`Money`), никогда `Double`.
- Месяц — `YearMonth`, никаких строковых операций над датами.

## Соглашения по коду
- Константы (тексты, ключи, размеры, цвета) → `Constants/` и `DesignSystem/`
- Типы/модели → отдельные файлы, не inline
- Бизнес-логика и состояние → во ViewModel/сервисах, не во View
- Доступ к данным → репозитории за протоколами
- Вью > ~150 строк — разбить
- Домен покрывается тестами обязательно: `cd HisobCore && swift test`

## UI / дизайн
- Только SwiftUI, без хардкода цветов/шрифтов — из `DesignSystem` (см.
  DESIGN_SYSTEM.md)
- Нативные ощущения: жесты, haptics, safe areas
- Доступность: VoiceOver-метки, Dynamic Type, контраст, Reduce Motion
- Все состояния обязательны: loading, empty, error
- Суммы — моноширинные цифры (`.monospacedDigit()`), чтобы не прыгали

## Готовность к API
- Данные через репозитории за протоколами; пока — in-memory реализация
- Замена на сеть/SwiftData = одна реализация `LedgerRepository`,
  View и ViewModel не трогаются

## Что НЕ делать
- Не хардкодить строки/цвета/размеры — из `Constants`/`DesignSystem`
- Не создавать вью, если есть в `DesignSystem` (см. DESIGN_SYSTEM.md)
- Не писать сеть/логику во View
- Не плодить слои ради слоёв — только где есть реальная граница
- Не использовать `Double` для денег
- Не сохранять данные «перезаписью всего массива» — только точечный CRUD по id
